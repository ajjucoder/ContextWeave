### Task B: Trace a prompt from `ChatView` to Codex and back into the thread UI

| Metric | ContextWeave | Grep+Read |

| Total tokens | 8,223 | 4,779 |
| Tool calls | 7 | 11 |

**What ContextWeave found:** It found `apps/web/src/components/ChatView.tsx`, `apps/web/src/wsNativeApi.ts`, and the WebSocket channel constant for domain events. `cw_grep("dispatchCommand")` and `cw_grep("ORCHESTRATION_WS_CHANNELS.domainEvent")` were the two useful recovery steps.

**What ContextWeave missed:** The capsule underused the 6k budget badly and missed the actual return path through `apps/server/src/orchestration/Layers/ProviderRuntimeIngestion.ts`, `apps/server/src/wsServer.ts`, `apps/web/src/routes/__root.tsx`, and the Zustand store sync path. `cw_flow("dispatchCommand")` never crossed the websocket boundary; it stalled at `WsTransport.request` and wandered into `LRUCache`. The suggested follow-up again used the wrong root and wrong argument name.

**Follow-up suggestions useful?** Mostly no. One `cw_read` on `ChatView` worked only because the symbol name was unique enough that the broken `file` arg did not matter.

**Winner:** Grep+Read

The correct flow is: `ChatView` dispatches through `createWsNativeApi().dispatchCommand` in `apps/web/src/wsNativeApi.ts`, the browser sends `ORCHESTRATION_WS_METHODS.dispatchCommand` to `apps/server/src/wsServer.ts`, the server routes to `ProviderCommandReactor`, then `ProviderService`, then `CodexAdapter`, then `CodexAppServerManager`. Streamed runtime output is ingested server-side, reprojected into orchestration domain events, broadcast on `ORCHESTRATION_WS_CHANNELS.domainEvent`, decoded by `wsNativeApi.onDomainEvent`, then applied in `apps/web/src/routes/__root.tsx` through `syncServerReadModel`, which `ChatView` consumes via selectors.

## Flaws Found

Ordered by severity. Each item includes what happened, likely root cause, and a suggested fix.

### P0 (Critical — blocks adoption)
1. **Suggested follow-up calls are malformed and can silently send you to the wrong file**: `cw_capsule("sendTurn")` suggested `cw_read(file:"src/provider/Layers/CodexAdapter.ts", symbol:"sendTurn")`. That path is not canonical for this repo, and the tool should have required `path`, not `file`. The follow-up silently ignored the bad arg and returned the integration fake in `apps/server/integration/TestProviderAdapter.integration.ts` instead of the real adapter. Root cause: the capsule follow-up generator is out of sync with the actual `cw_read` schema, and the read path validator appears to fall back to fuzzy symbol search instead of failing hard. Suggested fix: emit canonical repo-relative `path` values only, reject unknown args, and refuse to run `cw_read` when the supplied path cannot be resolved exactly.
2. **Broad retrieval does not find the actual bridge files that make end-to-end understanding possible**: on the ChatView-to-Codex flow and the web-state architecture task, the capsule missed key bridge files like `apps/server/src/orchestration/Layers/ProviderRuntimeIngestion.ts`, `apps/web/src/store.ts`, and `apps/web/src/routes/__root.tsx` while spending budget on nearby lexical noise. Root cause: retrieval/reranking seems to overweight local lexical matches and underweight cross-boundary bridge files, reducers, and event-ingestion points. Suggested fix: add graph-aware expansion that rewards transport boundaries, reducer/update sinks, and event fan-out/fan-in nodes.
3. **`cw_flow` is not reliable enough to replace explorer work**: it failed on both a direct code path and a websocket-mediated path. Instead of staying on the real call chain, it wandered into unrelated imports and utility cache operations. Root cause: the flow graph appears to mix generic import/call edges without enough symbol disambiguation, transport edges, or path-pruning heuristics. Suggested fix: disambiguate definitions before traversal, add special edges for transport/event channels, and penalize utility/library detours that do not preserve the queried intent.

### P1 (Important — degrades quality)
1. **Confidence is miscalibrated on vague and cross-cutting queries**: `cw_capsule("state")` returned `HIGH` confidence while surfacing contracts and desktop tests instead of the app’s actual state layer. Root cause: confidence appears tied to retrieval density and score saturation rather than answer correctness. Suggested fix: calibrate confidence against held-out task success and penalize answers dominated by tests, docs, or off-scope packages.
2. **Common-symbol ranking is not definition-first enough**: `sendTurn` returned an arbitrary implementation plus tests and integration fakes instead of clearly elevating the candidate production definitions. Root cause: exact symbol queries do not seem to have a strong “definition lane” separated from callers/consumers/tests. Suggested fix: rank exact definitions ahead of all call sites, then explicitly group additional definitions and test references below them.
3. **Path rendering drops repo roots in capsule output**: paths were reported as `src/...`, `server/src/...`, or `web/src/...` instead of `apps/server/src/...` and `apps/web/src/...`. Root cause: a display/serialization layer is stripping active-root prefixes inconsistently. Suggested fix: preserve canonical repo-relative paths through indexing, ranking, and response formatting so every follow-up call can be copied exactly.
4. **Budget utilization collapses on hard broad queries**: with an 8k budget, the two broadest queries used only 699 and 749 tokens. Root cause: the capsule loop appears to stop early once it has a thin answer, even when coverage is clearly low. Suggested fix: set a minimum utilization floor for low-confidence broad queries or keep expanding until marginal relevance actually falls off.
5. **Test and non-source pollution is too high in review mode**: exact symbol and concept queries repeatedly surfaced tests, integration harnesses, markdown plans, and contracts before the files a developer would actually open to make a change. Root cause: the review-mode ranker is not aggressively demoting tests/docs/non-executable artifacts. Suggested fix: add stronger priors for production source files in review mode, with an explicit escape hatch when the user asks for tests.

### P2 (Moderate — papercut)
1. **Reindex telemetry is not trustworthy**: forced reindex printed `435 files, 0 symbols (51ms)` and `1 files had parse errors`, but immediate status still reported 6,651 symbols. Root cause: the CLI likely reports only newly parsed symbols or stale counters instead of final index state. Suggested fix: make reindex output reflect the final DB totals and identify the parse-error file directly.
2. **`cw_recall` is dead on cold start**: on this repo it returned `No observations found for "state management"`. Root cause: the feature depends on prior observations but does not degrade gracefully when there are none. Suggested fix: label it explicitly as cold-start empty and consider seeding from docs, tests, or accepted capsules.
3. **`cw_stats` is honest but too easy to overread**: it reports session-local token usage cleanly, but it says nothing useful about cross-task effectiveness, and zeroed sessions make it look broken if you did not issue a capsule in that session. Root cause: the tool mixes “session telemetry” with language that sounds like product-level savings. Suggested fix: split stats into `session` vs `project` scopes and label savings estimates as heuristic, not factual.

## What Worked Well

- `cw_grep` was consistently useful. It behaved like a competent indexed grep and helped recover from capsule misses.
- `cw_overview` was the best architectural aid in this run. It found the real state files after the capsule failed to rank them well.
- `cw_status` gives a rich project profile quickly, including file/symbol counts and language distribution.
- When pointed at the correct file and symbol manually, `cw_read` returns clean, compact excerpts that are easy to scan.
