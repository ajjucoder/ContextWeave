## Flaws Found

Ordered by severity. Each issue below is independent and actionable.

### P0 (Critical — blocks adoption)
1. **Dependents are missing for real Convex symbols**: `cw_impact("convex/workspace.ts:resolveContext")` returned `No dependents found` even though the codebase has multiple real dependents in route-data hooks and tests. This breaks change-impact analysis on a core backend query. Root cause is likely missing or incomplete edge synthesis for Convex `api.*` query usage and generated API references, probably in [src/frameworks/plugins/convex.ts](/Users/aejjusingh/Developer/ContextWeave/src/frameworks/plugins/convex.ts), [src/core/event-edge-synthesis.ts](/Users/aejjusingh/Developer/ContextWeave/src/core/event-edge-synthesis.ts), and the traversal in [src/mcp/tools/impact.ts](/Users/aejjusingh/Developer/ContextWeave/src/mcp/tools/impact.ts). Fix by emitting graph edges for `useQuery`, `useMutation`, `useAction`, `convex.query`, and `api.namespace.symbol` references.
2. **Broad architectural retrieval misses the actual architecture**: On `route prewarm architecture and convex loaders`, the 8k-budget capsule used only 596 tokens and centered on generic `Route` exports instead of `src/lib/convexRouteData.ts` and the route `*.data.ts` files that actually implement prewarming. That means the flagship “understand the system” use case fails. Root cause is likely a mix of weak pivot selection and scattered packing, especially in [src/core/hybrid-ranker.ts](/Users/aejjusingh/Developer/ContextWeave/src/core/hybrid-ranker.ts), [src/core/reranker.ts](/Users/aejjusingh/Developer/ContextWeave/src/core/reranker.ts), [src/capsule/pivot-scorer.ts](/Users/aejjusingh/Developer/ContextWeave/src/capsule/pivot-scorer.ts), and [src/capsule/packer.ts](/Users/aejjusingh/Developer/ContextWeave/src/capsule/packer.ts). Fix by penalizing generic route boilerplate, boosting bridge files, and enforcing cluster-coherent packing before tail references.
3. **Capsule follow-up syntax does not match the actual `cw_read` API**: Capsules tell the user to run `cw_read(file: "...", symbol: "...")`, but the tool schema uses `path`, not `file`. That mismatch is directly visible in the source: [src/capsule/formatter.ts#L266](/Users/aejjusingh/Developer/ContextWeave/src/capsule/formatter.ts#L266) emits `file`, while [src/mcp/tools/read.ts](/Users/aejjusingh/Developer/ContextWeave/src/mcp/tools/read.ts) only accepts `path`. Following that suggestion for a file-only read produced `Error: provide path or symbol`. Fix by making `cw_read` accept `file` as an alias immediately, then unify all docs and formatter output on one parameter name.

### P1 (Important — degrades quality)
1. **Confidence is not trustworthy on hard queries**: `error handling across the app` came back `HIGH`, and the earlier share-link flow query came back `HIGH`, despite both missing major layers of the answer. That makes the confidence label actively dangerous. Root cause is likely in [src/capsule/confidence.ts](/Users/aejjusingh/Developer/ContextWeave/src/capsule/confidence.ts): lexical coverage and pivot coverage are being rewarded without a strong enough penalty for missing required cross-layer files. Fix by making confidence depend on layer completeness, bridge-file presence, and observed follow-up miss rates.
2. **Budget utilization is catastrophically low on the queries where ContextWeave most needs budget**: 10% utilization for the share-link flow and 7% for route prewarm architecture is not a small miss; it means the packer never assembled enough useful context. Root cause is likely shared between retrieval and packing, especially [src/capsule/packer.ts](/Users/aejjusingh/Developer/ContextWeave/src/capsule/packer.ts). Fix by adding a backfill pass when utilization is under target, and by preferring dense story-complete file groups over sparse symbol scatter.
3. **`cw_flow` is not robust enough for realistic UI-to-backend tracing**: `cw_flow({source:"SharePage"})` drifted into import chains, and `cw_flow({source:"createRoutePrewarmIntent"})` found nothing. That means flow tracing is weak exactly where it should be strongest: callbacks, framework edges, and indirect data access. Root cause is partly in [src/mcp/tools/flow.ts](/Users/aejjusingh/Developer/ContextWeave/src/mcp/tools/flow.ts), which still allows import-heavy paths to dominate, and partly in missing higher-order/framework edges from [src/core/event-edge-synthesis.ts](/Users/aejjusingh/Developer/ContextWeave/src/core/event-edge-synthesis.ts). Fix by deprioritizing passive import edges and synthesizing stronger callback/server-action/framework edges.
4. **Follow-up read ranking is frequently wrong**: Task A suggested `handleDeleteProject`; Task B suggested cleanup helpers and UI components; Task C suggested more intent-handler snippets before the core library. That wastes tokens and makes the user do manual rescue. Root cause is likely [src/capsule/formatter.ts](/Users/aejjusingh/Developer/ContextWeave/src/capsule/formatter.ts) and [src/capsule/generator.ts](/Users/aejjusingh/Developer/ContextWeave/src/capsule/generator.ts), where follow-ups appear to be ranked by surface overlap instead of missing-story closure. Fix by ranking follow-ups using uncovered pivots, dependency gaps, and cross-layer bridges.
5. **`cw_stats` overpromises savings without measured evidence**: The stats tool reported `Estimated savings vs targeted grep+read: ~1,564 tokens`, but the measured outcome in this review was the opposite: ContextWeave used 12,829 more tokens than grep+read. Even if the estimate is session-scoped, it is too optimistic and too easy to misread. Root cause is likely the stats formatter in the built server and/or logic adjacent to [src/mcp/tools/stats.ts](/Users/aejjusingh/Developer/ContextWeave/src/mcp/tools/stats.ts). Fix by removing savings estimates unless a real baseline exists, or by labeling them as heuristic with clear scope.

### P2 (Moderate — papercut)
1. **`cw_overview` is almost query-agnostic**: For an architectural question it returned a nice repo inventory, but not a useful architectural overview. That makes it hard to know when to use the tool. Likely root cause: [src/mcp/tools/overview.ts](/Users/aejjusingh/Developer/ContextWeave/src/mcp/tools/overview.ts). Fix by either making it query-aware or renaming it to reflect that it is mostly structural metadata.
2. **`cw_recall` is mostly an echo of prior capsule observations**: On `share links` it only replayed one earlier note. That is not useful memory; it is session noise. Likely root cause: [src/mcp/tools/recall.ts](/Users/aejjusingh/Developer/ContextWeave/src/mcp/tools/recall.ts) plus passive-memory storage in [src/memory/passive.ts](/Users/aejjusingh/Developer/ContextWeave/src/memory/passive.ts). Fix by separating durable patterns from throwaway capsule summaries.
3. **Text and structured outputs can disagree**: On the `resolveContext` exact-symbol test, the text header said `Confidence: MEDIUM` while the structured JSON said `LOW`. That kind of mismatch makes downstream tooling brittle. Root cause is likely duplicate formatting paths or `dist` vs `src` drift between [src/capsule/formatter.ts](/Users/aejjusingh/Developer/ContextWeave/src/capsule/formatter.ts) and the built server. Fix with a snapshot test asserting that text and structured confidence labels are identical for the same capsule.
