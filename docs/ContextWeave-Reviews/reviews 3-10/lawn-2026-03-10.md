## Flaws Found

### P0 (Critical — blocks adoption)

1. **Flow tracing is completely non-functional**: `cw_flow` returned "No outgoing flows found" for every query (4/4 attempts). It cannot trace direct calls, Convex API calls, callback chains, or any cross-boundary flows. For a tool that claims to trace "call flow between symbols," returning zero results 100% of the time is a critical failure. Root cause: likely only tracks `import` edges, not actual call-site edges within function bodies. Fix: implement call-graph extraction from AST — for each function, record what other symbols it calls, not just what it imports.

2. **First capsule for auth query returned entirely irrelevant content**: Querying "authentication and authorization patterns" returned sign-in page CSS styling instead of the auth module, RBAC system, or permission checking functions. The word "auth" in the file path `app/routes/auth/` outweighed the actual authentication logic in `convex/auth.ts`. Root cause: path-based relevance scoring dominates over content-based relevance. Fix: when query contains "authentication"/"authorization", prioritize files exporting functions with `require`/`check`/`verify`/`assert` in their names over files in `/auth/` directories that only render UI.

### P1 (Important — degrades quality)

1. **Capsule body omits content from #1 relevance file**: Task A's capsule listed `CommentInput.tsx` as relevance 1.0 with matched symbols `handleSubmit, CommentInput, handleKeyDown`, but the capsule text body showed zero lines from that file. Instead it showed DB query snippets from 5 other files. Root cause: the packer selected high-centrality symbols (DB queries appearing in many files) over the actually-relevant symbols from the query-matched file. Fix: ensure the #1 relevance file always gets budget allocation for its matched symbols before filling with cross-reference snippets.

2. **Large budgets are wasted — 17-21% utilization on 8K budgets**: Two queries with 8,000 token budgets used only 1,323 and 1,683 tokens respectively, despite abundant relevant content existing (VideoPlayer.tsx alone is 1,109 lines / ~52 symbols). Root cause: the packer stops adding content after exhausting high-relevance results, even when budget remains. It doesn't backfill with lower-relevance-but-still-useful content. Fix: implement budget backfilling — if utilization is below 50%, progressively lower the relevance threshold and pack additional context.

3. **Confidence is miscalibrated on pattern-matching queries**: "error handling" received HIGH confidence + 100% coverage, but the results included `handleTimestampClick`, `handleTimeUpdate`, and `DEFAULT_HEARTBEAT_INTERVAL_MS` — symbols with zero relation to error handling. The word "handle" in function names triggered false positives that the confidence scorer didn't detect. Root cause: confidence is based on coverage metrics (pivot count, dependency coverage), not answer quality. Fix: add a semantic coherence check — if returned symbols share no semantic relationship to the query beyond substring matches, reduce confidence.

4. **Symbol lookup can't find Convex mutation exports**: `cw_flow(source: "createComment")` returned "No symbol found matching" despite `convex/comments.ts` exporting `const create = mutation({...})` which is consumed as `api.comments.create`. Root cause: CW indexes by the variable name (`create`) not the API path (`comments.create`). Fix: for Convex projects, index mutation/query/action exports with their fully-qualified API path as an alias.

### P2 (Moderate — papercut)

1. **`cw_overview` query focus is unhelpful**: The "Query Focus" section lists files with "no direct symbol name match" without explaining why they're relevant. Six of eight matched files had no explanation, making the focus section noise rather than signal. Fix: only include files in query focus that have at least one semantic or symbol match; drop "no direct match" entries.

2. **`cw_recall` can't match broad queries to stored observations**: "architecture decisions and patterns" returned nothing despite 8 observations existing. The BM25 search requires keyword overlap with observation text, but stored observations are convention-level notes from CLAUDE.md. Fix: store observations with auto-generated tags/categories that enable broader recall.

3. **`cw_stats` inflates savings estimates**: Reports "72% reduction" based on estimated grep+read cost of ~65,440 tokens, but actual measured grep+read cost across 3 tasks was ~18,530 tokens. The estimate assumes naive full-file reads that no real workflow would perform. Fix: base estimates on realistic grep+read patterns (targeted reads, not full files), or at minimum disclose the estimation methodology.

4. **`cw_read` paths are ambiguous**: `cw_read` follow-up suggestions use bare filenames like `-layout.tsx` and `route.tsx` instead of full paths like `app/routes/dashboard/-layout.tsx`. In a project where multiple files could match these names, this creates confusion. Fix: always use full relative paths from project root in suggestions.

5. **Duplicate content across capsules**: When multiple capsules are generated in a session, the same code snippets appear repeatedly (e.g., `deleteTeam` handler appeared in 3 separate capsules). The `[previously shown]` marker helps but still consumes tokens. Fix: implement session-aware deduplication that actually excludes previously-shown content from token counting.

## What Worked Well

1. **Symbol-level precision is excellent**: All 3 exact symbol lookups placed the definition at rank #1 with full source. When you know the symbol name, `cw_capsule` is fast and accurate.

2. **`cw_impact` is genuinely useful**: Found all 17 consumers of `requireVideoAccess` across 5 files instantly. This is the kind of analysis that's tedious to do with grep (you'd need to grep, then filter out non-import references, then check each file). Impact analysis is CW's strongest tool.

3. **Multi-level compression is well-designed**: The `[full]`, `[summary]`, `[skeleton]`, `[reference]` compression levels are smart. Summaries include function signatures and dependency lists, which is often enough context without reading the full source.

4. **Budget-constrained capsules (1,200 tokens) are efficient**: The 1,200-token symbol lookups achieved 92-99% utilization and delivered focused, useful results. CW works best at small budgets for targeted queries.

5. **Diagnostics and quality notes are honest**: When coverage is poor, CW says so. The "quality notes" and "diagnostics" sections correctly identified `lexical_mismatch`, `packing_scatter`, and low coverage conditions. The self-awareness is better than the actual fix — but at least it doesn't hide problems.

6. **Second capsule for auth (scoped to convex/) was good**: Once I provided exact symbol names and directory scope, the capsule delivered the auth functions, their usage in mutations, and the permission pattern across modules. The tool responds well to precise, scoped queries.

**Verdict:** CW is a useful **first pass** tool for symbol lookups and impact analysis. It cannot replace Grep+Read for:
- Broad architectural understanding
- Tracing flows across Convex action/mutation boundaries
- Understanding async patterns (webhooks, callbacks)
- Queries that require semantic understanding vs keyword matching

The ideal workflow is: `cw_capsule` first for orientation → `cw_impact` for blast radius → Grep+Read for anything the capsule missed. CW saves tokens on the "find the right files" step but can't replace actually reading those files.
