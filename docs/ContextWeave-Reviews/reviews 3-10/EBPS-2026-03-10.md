## Flaws Found

### P0 (Critical — blocks adoption)

1. **Confidence is grossly miscalibrated on semantic queries**: Query "error handling patterns across the application" returned HIGH confidence / VERY_LOW uncertainty, but the answer contained zero error handling code. It matched the word "patterns" to regex patterns and glob patterns. Root cause: confidence likely based on retrieval coverage (how many pivots were found) rather than semantic relevance of those pivots. Fix: confidence scoring must penalize when query intent is abstract/architectural but retrieved symbols are concrete/literal. A keyword overlap metric is insufficient for natural language queries.

2. **Budget under-utilization with target truncation**: When querying "SmartExtractor class" with 8000-token budget, the target class was truncated ("256 more lines") while 27% of budget was used — and that 27% included 4 irrelevant test fake classes shown in full. The system has budget to show the full target but spends it on noise instead. Root cause: likely in the packer's priority logic — it fills budget with top-N symbols by score rather than ensuring the primary target is fully expanded before adding secondary results. Fix: if query exactly matches a class/function name, that symbol MUST be fully expanded before any other symbol gets budget. Primary target truncation while noise is shown is the worst possible outcome.

### P1 (Important — degrades quality)

1. **`VerificationResult` noise pollution across all capsules**: This 99-line class appeared in ALL 3 symbol-lookup stress tests and most task capsules, consuming 500-1000 tokens each time. It has high centrality (many edges) but is rarely what the user is looking for. Root cause: centrality-based ranking over-weights hub nodes. Fix: add a diminishing returns penalty for symbols that appear in many capsules within a session, or reduce weight for "container" types (dataclasses with many fields that are referenced everywhere).

2. **Flow tracing exhausts path limit on one branch**: `cw_flow` for `_run_single_client` found 10 paths, all through the extraction branch. Download, verify, and report branches were never explored. Root cause: the flow tracer likely does DFS/BFS and returns the first N paths found, which all happen to be through the same initial branch. Fix: diversify paths across distinct first-hop targets before depth-exploring any single branch. Each direct callee of the source should get at least one path.

3. **Cannot trace incoming callers (reverse flow)**: `cw_flow` for `estimate_frontage` (a leaf function) returned "No outgoing flows found." There's no way to ask "who calls this function?" via flow tracing. `cw_impact` partially fills this gap but its output format is different. Root cause: `cw_flow` is designed as outgoing-only. Fix: add a `direction: "incoming" | "outgoing" | "both"` parameter, or document that `cw_impact` is the correct tool for finding callers.

4. **cw_stats "savings" claim contradicts measured results**: `cw_stats` reported "63% reduction" vs grep+read, but measured task-based comparison showed CW cost 46% MORE. Root cause: stats estimates grep+read cost as sum of all file reads that would be needed, but doesn't account for grep being targeted (users don't read entire files). Fix: track actual parallel grep+read token costs from the same session for honest comparison, or add a disclaimer that savings are estimated, not measured.

### P2 (Moderate — papercut)

1. **Test fixtures rank above source code**: In the SmartExtractor capsule, `_FakeRow`, `_FakeRows`, `_FakePage`, `_FakeResponse` from test files were shown in full while the target class was truncated. Root cause: all indexed symbols compete equally regardless of whether they're test fixtures or production code. Fix: apply a scoring penalty for symbols in test files when the query doesn't mention tests.

2. **"previously shown" summaries waste follow-up budget**: In multi-capsule sessions, symbols shown in earlier capsules get `[previously shown]` markers instead of content. This saves tokens within a capsule but forces follow-up reads if the user needs the content again. The capsule doesn't know what the user remembers from earlier. Root cause: session-aware deduplication. Fix: this is arguably correct behavior for token savings, but the follow-up suggestion should auto-include these symbols with higher priority.

3. **`cw_recall` returns nothing for established project context**: "No observations found" for "architecture cleanup refactoring" despite the project having had major cleanup work done and 16 stored observations. Root cause: BM25 keyword matching may not overlap with observation text. Fix: check what terms the 16 observations actually contain and improve recall's matching to handle synonyms or broader topic matching.

4. **`cw_overview` query focus is filename-only**: For "pipeline orchestration," it only matched the filename `ebps_pipeline.py`. It didn't surface `_run_single_client`, `main`, or any actual orchestration symbols. Root cause: query focus section appears to do substring matching on file/symbol names rather than semantic search. Fix: apply the same retrieval logic as capsules to the query focus section.

## What Worked Well

1. **`cw_impact` is genuinely useful**: Impact analysis for `SmartExtractor` correctly traced the full dependency chain through extract_document → extract_client_folder → _run_single_client → main across both entry points. This would take 3-4 grep calls to reconstruct manually. This is ContextWeave's strongest tool.

2. **Definitions always rank #1 in capsules**: All 3 symbol-lookup tests placed the definition first. The AST-aware ranking correctly prioritizes definitions over callers/consumers. This is table-stakes but it works.

3. **Multi-level compression is clever**: The skeleton/summary/full/reference compression levels are well-designed. Seeing `[skeleton]` for a function signature vs `[full]` for the target creates useful information density when it works correctly.

4. **`cw_flow` for direct calls within a single branch is accurate**: The `extract_compliance` flow trace correctly followed PyMuPDF → quality check → OCR fallback → parse_compliance_local → helpers. Every hop was verified accurate.

5. **Session deduplication**: `[previously shown]` markers prevent re-sending large symbols across capsules within a session. This genuinely saves tokens when browsing related queries.
