## Flaws Found

### P0 (Critical — blocks adoption)

1. **Worktree duplication wastes 40-50% of every capsule budget**: `.claude/worktrees/priceless-bardeen/` contains an identical copy of every source file. ContextWeave indexes both copies and returns both in every capsule, doubling token usage with zero information gain. On a 1200-token budget, this means ~600 tokens of useful content. → Root cause: the indexer doesn't recognize `.claude/worktrees/` as a git worktree that should be excluded. → Fix: Add `.claude/worktrees/` to the default exclusion list, or detect git worktrees and deduplicate results that share identical content hashes.

2. **Cross-boundary flow tracing is non-functional**: In a Tauri app (or any app with IPC, HTTP, events, or message passing), `cw_flow` cannot trace the most important connections — the ones that cross language/process boundaries. `emit_all("gap_start")` → `listen('gap_start')` is the core architectural pattern of this app, and CW is blind to it. → Root cause: flow analysis only tracks AST-level call edges within a single language. String-based event names connecting Rust emitters to TypeScript listeners are invisible. → Fix: Implement cross-language event/string matching. When `emit_all("X")` appears in Rust and `listen('X')` appears in TypeScript, create a synthetic edge. Same pattern works for HTTP routes, Redux actions, etc.

3. **cw_impact returns "no dependents" for the most-used struct**: `cw_impact("SessionState")` returned 0 dependents despite SessionState being the core shared state used across 5+ functions in multiple files. → Root cause: likely confused by having 4 definitions (2 real + 2 worktree dupes) and failing to resolve any of them. The impact analysis may only track explicit import edges and miss `use` statements or struct field access patterns. → Fix: Impact analysis must handle multiple definitions gracefully (pick the canonical one) and trace through Rust `use`/`mod` imports and field access patterns.

### P1 (Important — degrades quality)

1. **Confidence is miscalibrated for broad queries**: Task B capsule reported HIGH confidence while missing the trigger (`run_session` loop) and the listener (`listen('gap_start')`). A developer trusting HIGH confidence would write incorrect code. → Root cause: confidence appears to be based on pivot coverage (56% was enough for HIGH?) rather than whether the answer would be actionable. → Fix: Confidence should be calibrated against "would a developer trust this enough to write code?" For multi-file flow queries, require coverage of both initiator and responder to claim HIGH.

2. **Severe budget underutilization on large budgets**: 12% and 28% utilization on 8000-token budgets. The capsule chooses summaries over full source even when the budget easily accommodates all relevant symbols in full. → Root cause: the packer's compression strategy appears to be fixed (summary mode) regardless of remaining budget. It doesn't upsize to full source when there's abundant budget remaining. → Fix: When budget utilization is below 50%, expand compressed symbols to full source starting from highest relevance score.

3. **Capsules miss the frontend state layer consistently**: In Tasks A, B, and C, the Zustand store (`sessionStore.ts`), `App.tsx` event listeners, and TypeScript types were consistently deprioritized or omitted. The capsule has a Rust bias — likely because Rust files have more AST symbols and higher centrality scores. → Root cause: centrality scoring favors the Rust backend because it has more inter-symbol edges. The TS frontend has fewer symbols (hooks, components) but they're equally important for understanding the app. → Fix: Consider language-balanced scoring, or boost symbols that appear at IPC boundaries (event listeners, invoke calls).

### P2 (Moderate — papercut)

1. **cw_stats claims 27% savings that don't exist**: Self-reported stats say "estimated savings: ~5,152 tokens (27% reduction)" but manual task comparison shows CW cost 88% more than grep+read. The "estimated grep+read cost" appears to count what WOULD have been read if you read every file the capsule touches, not what a targeted grep+read actually costs. → Fix: Track actual grep+read token usage in parallel (shadow mode) to get honest comparisons, or at minimum caveat that the estimate is theoretical.

2. **`cw_flow` returns 0 outgoing flows for `run_session`**: `run_session` calls `state.lock().unwrap()`, `s.elapsed_ms()`, `app.emit_all()`, `app.get_window()` — none traced. → Root cause: method calls on variables (`s.elapsed_ms()`, `app.emit_all()`) aren't being resolved to their definitions because they require type inference that the AST parser doesn't perform. → Fix: For Rust, resolve method calls through the type system (at least for local `let` bindings with known types).

3. **Follow-up read suggestions point to worktree copies**: Every "Follow-Up Reads" section suggests `cw_read(file: ".claude/worktrees/priceless-bardeen/...")` — the worktree copy instead of the canonical source file. → Fix: Once worktree dedup is fixed, this resolves automatically.

4. **Duplicate `[previously shown]` markers inflate symbol counts without adding information**: When a symbol was shown in a previous capsule, CW includes `[summary] [previously shown]` markers that consume tokens without content. In a single session with many capsules, these accumulate. → Fix: When a symbol is fully previously shown, omit it entirely rather than including a placeholder that costs tokens.

## What Worked Well

1. **Exact symbol lookup is excellent.** When querying a specific function name (`generate_gap_times`, `useSessionStore`, `dismiss`), the definition always appeared as result #1 with correct context. This is the strongest use case.

2. **Multi-level compression is genuinely useful.** The capsule's ability to show `[full]` for the most important symbol, `[summary]` with signature+deps for secondary symbols, and `[skeleton]` for types is a good information density strategy. When it works (which requires the worktree bug to be fixed), it provides better overview than reading raw files.

3. **AST-aware symbol boundaries.** Unlike grep which returns lines, CW returns complete function bodies. For `generate_gap_times`, you get the full function without needing to guess line ranges. This is genuinely better than grep for understanding a function.

4. **Honest LOW confidence on hard queries.** For "error handling" and "state synchronization", confidence was honestly LOW. The problem is the one case where it said HIGH and was wrong (Task B).

5. **`cw_impact` found the right caller for `run_session`.** Despite issues with `SessionState`, the impact analysis correctly traced `run_session` → `start_session` (its caller). When it works, it's useful.
