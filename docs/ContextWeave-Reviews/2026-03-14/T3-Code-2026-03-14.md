## Flaws Found

Ordered by severity. Each flaw is one issue.

### P0 (Critical — blocks adoption)
1. **Capsule follow-up commands are wrong and can send the user to the wrong file**: In Task A, the capsule suggested `cw_read(file: "src/provider/Layers/CodexAdapter.ts", symbol: "sendTurn")`. Using that literally returned `apps/server/integration/TestProviderAdapter.integration.ts:sendTurn`, not the real runtime definition. Root cause: the formatter emits `file` while `cw_read` expects `path`, and unknown keys are silently ignored, so symbol lookup falls back to global fuzzy resolution. Likely root cause files: `src/capsule/formatter.ts`, `src/mcp/tools/read.ts`. Suggested fix: emit `path`, accept `file` as an alias only if you must, and make unknown-key schema mismatches fail loudly.
2. **Broad flow capsules do not retrieve the actual flow, but confidence still lands at MEDIUM**: The `thread.turn.start` flow capsule missed the actual UI -> WS -> decider -> reactor chain and instead ranked one-line `thread` locals, a `PROVIDER` constant, route stubs, and checkpoint noise. Root cause: ranking appears to overweight common lexical tokens (`thread`, `start`, `flow`) and underweight command/event boundary anchors. Likely root cause files: `src/capsule/generator.ts`, `src/capsule/pivot-scorer.ts`, `src/capsule/confidence.ts`. Suggested fix: require layer coverage for flow queries before MEDIUM confidence, boost event/contract anchors, and strongly demote one-line locals and test files.
3. **`cw_flow` fails on real production call chains that matter**: It could not trace `CodexAdapter.sendTurn -> CodexAppServerManager.sendTurn`, could not trace `sendTurnForThread -> CodexAdapter.sendTurn`, and even claimed `readFromSequence` had no production callers. Root cause: member-call/service-call resolution is too weak; callback/transport boundaries are effectively invisible. Likely root cause files: `src/mcp/tools/flow.ts` plus whatever edge construction feeds it. Suggested fix: add receiver/type-aware edge resolution, especially for `object.method(...)` service patterns, and explicitly model transport/event bridges.

### P1 (Important — degrades quality)
1. **Budget utilization is nowhere near the product claim on broad tasks**: The two 8000-token queries used 15% and 36% of budget while still missing important context. Root cause: packer/refill logic stops early or does not widen the candidate pool enough when coverage is poor. Likely root cause files: `src/capsule/packer.ts`, `src/capsule/generator.ts`. Suggested fix: enforce a minimum fill target for broad/review queries or downgrade confidence much harder when utilization stays low.
2. **Default retrieval is badly polluted by tests and non-source files**: `cw_status` warned that 93% of indexed files were non-source, and task outputs repeatedly surfaced tests ahead of runtime code. Root cause: indexing and/or ranking does not sufficiently demote tests/docs/generated artifacts by default. Likely root cause files: `src/utils/config.ts`, `src/capsule/generator.ts`, `src/mcp/tools/status.ts`. Suggested fix: apply stronger default test/doc demotion in ranking, not just indexing warnings.
3. **`cw_reindex` is misleading as an operator signal**: It reported `435 files, 0 symbols (57ms)` on this repo, which looks like a full reindex succeeded absurdly fast. CLI logs later showed it had actually skipped all unchanged files. Root cause: the tool summary reports only newly processed symbols but looks like a total-index summary. Likely root cause files: `src/mcp/tools/reindex.ts`, `src/cli/commands/reindex.ts`, `src/core/indexer.ts`. Suggested fix: clearly separate `processed`, `skipped`, and `total indexed`, and label whether the run was incremental or cold.
4. **`cw_impact` mixes useful dependents with low-signal variable/test noise**: On `sendTurn`, it did find `sendTurnForThread`, but it also surfaced tests and weird locals such as `make`. Root cause: impact ranking does not sufficiently weight runtime paths and symbol kinds. Likely root cause files: `src/mcp/tools/impact.ts`. Suggested fix: rank runtime defs above tests, and demote local variables unless no stronger dependents exist.

### P2 (Moderate — papercut)
1. **`cw_recall` is basically inert for code-understanding unless prior memory exists**: For `orchestration engine`, it returned nothing. That is not wrong, but it means the tool is not helping with first-pass code comprehension. Root cause: recall is memory-only and not clearly separated from code/doc retrieval in user expectations. Likely root cause files: `src/mcp/tools/recall.ts`. Suggested fix: make the limitation explicit in the tool description or blend in doc/code note retrieval.
2. **`cw_stats` overstates how meaningful its quality metrics are**: Budget utilization was useful, but `first-pass rate: 100%` and `correction rate: 0%` only meant I did not call more tools in that server session. That is not answer quality. Root cause: follow-up frequency is being framed as success. Likely root cause files: `src/mcp/tools/stats.ts`. Suggested fix: relabel these as operator-behavior metrics, not answer-quality metrics.

## What Worked Well

- Exact symbol ranking on precise symbol queries was solid. `sendTurn`, `dispatchCommand`, and `readFromSequence` all surfaced a definition at rank #1 in capsule output.
- `cw_grep` was the best part of the toolset. It was fast, gave line-aware snippets, and attached enclosing symbol context.
- Low confidence was honest on the hardest architecture query.
- `cw_overview` was a decent subtree/orientation tool for `apps/server/src`.
