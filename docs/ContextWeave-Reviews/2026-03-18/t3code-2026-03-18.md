## Flaws Found

Ordered by severity. Each item includes what happened, likely root cause, and how to fix it.

### P0 (Critical — blocks adoption)
1. **Flow tracing produces bogus answers for real event-driven work**: `cw_flow(source: "apps/web/src/components/ChatView.tsx:onSend")` could not resolve a real file-qualified symbol, and `cw_flow(source: "thread.turn.start")` traced into toast helpers instead of the orchestration path. The likely root cause is in `src/mcp/tools/flow.ts`: it resolves names with naive `.` splitting and fuzzy symbol lookup instead of using the file-qualified parsing logic that already exists in `src/mcp/tools/symbol-resolution.ts`, and it has no separate model for event/HTTP edges. Fix: support file-qualified symbol references in `cw_flow`, refuse to fuzzy-match event strings to arbitrary symbols, and add explicit event/transport edges to the graph.
2. **Capsule output corrupts canonical paths, breaking its own follow-up guidance**: broad/task capsules returned machine-readable paths like `store.ts`, `web/src/...`, and `server/src/...`, and then used those same truncated paths in `suggestedReads`. That makes the structured output unsafe for automation. The likely root cause is path shortening in `src/capsule/generator-helpers.ts` and `src/capsule/formatter.ts`: display paths are being written back into structured output instead of keeping repo-relative canonical paths there. Fix: keep full repo-relative paths in all structured fields and only shorten paths in human-facing text.
3. **Broad/task capsules do not replace grep+explore; they force it back in through the side door**: on the two hard tasks, CW only succeeded after I manually drove `cw_grep` + `cw_read` like a slower grep/read workflow. Tokens were worse on every task, and much worse on end-to-end flow work. The likely root cause is in `src/capsule/generator.ts` and `src/capsule/packer.ts`: ranking overweights lexical/UI-local matches, while packing/refill heuristics still fail to assemble coherent multi-boundary stories even with lots of unused budget. Fix: optimize for chain completeness across transport/event/service boundaries, not just per-symbol relevance, and aggressively backfill coherent paths until either a target utilization or an explicit “no more relevant material” condition is reached.

### P1 (Important — degrades quality)
1. **`cw_stats` reports misleading utilization and mislabeled scope**: the tool said “Budget utilization: 56%” and “Quality: Budget utilization healthy” for a session that actually used 8,269 out of 20,000 budgeted tokens, which is 41%. It also printed “Indexed: 30 files, 103 symbols” even though the index had 435 files and 6,651 symbols. The likely root cause is in `src/mcp/tools/stats.ts`: it averages per-capsule utilization instead of computing total used / total budget, and it labels session-coverage counters as index counters. Fix: show both aggregate and per-capsule utilization, and rename the session numbers to “session-covered files/symbols”.
2. **`cw_status` misclassifies monorepo source as non-source and overstates excluded roots**: it warned that 93% of indexed files were from non-source directories even though the repo is mostly `apps/*/src` and `packages/*/src`. It also reported `apps [.gitignore]` as an excluded root while indexing hundreds of files under `apps`. The likely root cause is split across `src/mcp/tools/status.ts` and `src/utils/project-profile.ts`: source detection only checks prefixes like `src/`, `lib/`, `app/`, `packages/`, which misses `apps/web/src/...`, and ignore-root extraction collapses nested ignore patterns down to top-level `apps`. Fix: classify source by full repo-relative patterns and only report a top-level root as excluded when the root itself is ignored.
3. **Confidence calibration is too generous on vague conceptual queries**: `cw_capsule("error handling")` returned `HIGH` confidence with `very_low` uncertainty while mostly surfacing generic `error` variables and `catch` blocks. `cw_capsule("state management")` reported `MEDIUM` confidence with `low` uncertainty despite ranking irrelevant desktop and giant UI files above the real architecture split. The likely root cause is in `src/capsule/confidence.ts` plus the lexical/ranking stack in `src/capsule/generator.ts`: the confidence model rewards low-noise clean-looking retrieval without enough penalty for generic term matches or wrong-layer results. Fix: penalize generic tokens like `error`, require cross-layer concept coverage for architectural queries, and calibrate against held-out evaluation tasks instead of internal heuristics.

### P2 (Moderate — papercut)
1. **Exact symbol ranking still lets wrappers and tests crowd out canonical runtime definitions**: `normalizeModelSlug` and `syncServerReadModel` were fine, but `getSnapshot` put a web RPC wrapper first and the raw grep top hit was a test double. For common names, the ranking is not opinionated enough about which definition is the one a developer actually wants. The likely root cause is in `src/mcp/tools/symbol-resolution.ts` and the capsule scorer: exact-name resolution leans on centrality and lexical similarity without a strong preference for exported runtime implementations over wrappers/tests. Fix: for exact-symbol queries, bias hard toward non-test runtime definitions and let wrappers/tests win only when the query path or owner explicitly points there.
2. **`cw_recall` is too lexically loose to be trusted**: `cw_recall("provider turn flow")` returned a stale-ish observation about `state management`, which is not useful memory. The likely root cause is in `src/mcp/tools/recall.ts`, which uses BM25 over stored notes without stronger intent/topic filtering. Fix: add semantic retrieval or at least scope-aware reranking so recall does not regurgitate loosely related capsule notes.

## What Worked Well

- `cw_impact` was genuinely useful. On `normalizeModelSlug`, it surfaced real transitive dependents across web and server much faster than I expected.
- `cw_read` is solid once you already know the exact file or symbol. The bounded excerpts were reliable and readable.
- Indexing speed was good for this repo size: about 6 seconds for 435 indexed files and 6,651 symbols.
- Exact symbol lookup can work on clean cases. `normalizeModelSlug` and `syncServerReadModel` both had the definition at rank #1.
