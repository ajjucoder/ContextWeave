**Follow-up suggestions useful?** No. The main suggestion was to read `VariationSiteSettingsPage`, which is a caller example, not the core abstraction you need first to understand `updateSite`.

## Flaws Found

Ordered by severity. Each issue is written as one independently actionable flaw.

### P0 (Critical — blocks adoption)
1. **Broad capsules do not anchor on the actual flow files**: the public inquiry flow query missed `src/app/api/submit-inquiry/route.ts`, led with unrelated `src/lib/supabase/storage.ts` and `src/lib/supabase/auth.ts`, and suggested `HowItWorks` from a landing page. That means the flagship “one capsule replaces exploration” promise fails exactly on the kind of end-to-end question ContextWeave is supposed to own. Likely root cause is broad-query decomposition and ranking/pivot weighting in [`src/capsule/query-decomposer.ts`](/Users/aejjusingh/Developer/ContextWeave/src/capsule/query-decomposer.ts), [`src/core/hybrid-ranker.ts`](/Users/aejjusingh/Developer/ContextWeave/src/core/hybrid-ranker.ts), [`src/capsule/pivot-scorer.ts`](/Users/aejjusingh/Developer/ContextWeave/src/capsule/pivot-scorer.ts), and packing in [`src/capsule/packer.ts`](/Users/aejjusingh/Developer/ContextWeave/src/capsule/packer.ts). Fix: when a query mentions “flow”, “submission”, “storage”, “email”, etc., strongly boost route handlers and files connected by literal fetch paths or framework-entry edges, and aggressively demote unrelated generic `response` helpers.
2. **Common-symbol lookup is not reliable enough to replace grep**: `updateSite` produced internally inconsistent ranking. The capsule text said it was “showing top-ranked from `src/lib/dataLayer.ts`,” but the actual ranked file list put `lib/sitesStore.ts` first. `cw_grep("updateSite")` was even worse: a test mock outranked any real runtime definition. That destroys trust on narrow tasks. Likely root cause is ambiguous-symbol disambiguation and ordering drift between the narrative formatter and structured ranking in [`src/capsule/generator.ts`](/Users/aejjusingh/Developer/ContextWeave/src/capsule/generator.ts), plus definition ranking in [`src/mcp/tools/search.ts`](/Users/aejjusingh/Developer/ContextWeave/src/mcp/tools/search.ts). Fix: add an exact-definition fast path that prefers exported runtime definitions over tests, mocks, interface members, and incidental string hits, and ensure the human-readable summary cannot contradict the actual ranked file order.
3. **`cw_impact` under-reports the dependents that matter to a developer**: `cw_impact("src/lib/dataLayer.ts:updateSite")` returned only the local wrapper function inside `dataLayer.ts` and missed the real blast radius across settings, style, packages, preview, and dashboard pages that call `useSiteDataLayer().updateSite`. That is not a minor miss; it makes the tool unsafe for change planning. Likely root cause is edge extraction/resolution gaps for returned object members and destructured hook consumers in [`src/core/parser.ts`](/Users/aejjusingh/Developer/ContextWeave/src/core/parser.ts), [`src/core/indexer.ts`](/Users/aejjusingh/Developer/ContextWeave/src/core/indexer.ts), and traversal logic in [`src/mcp/tools/impact.ts`](/Users/aejjusingh/Developer/ContextWeave/src/mcp/tools/impact.ts). Fix: capture object-member usage edges from hook return values, then add a regression fixture around `useSiteDataLayer -> updateSite`.

### P1 (Important — degrades quality)
1. **Confidence is still too generous on bad broad answers**: both `error handling across the app` and `api routes patterns` returned visibly incomplete/off-topic results while still reporting `MEDIUM` confidence. That is not honest calibration. Likely root cause is confidence scoring in [`src/capsule/confidence.ts`](/Users/aejjusingh/Developer/ContextWeave/src/capsule/confidence.ts) and coverage assembly in [`src/capsule/generator.ts`](/Users/aejjusingh/Developer/ContextWeave/src/capsule/generator.ts) relying too much on retrieval counts and too little on layer/path coverage. Fix: broad-query confidence should require coverage of the expected architectural layers and a minimum fraction of first-party route/helper files.
2. **Follow-up suggestions are often actively wrong**: the inquiry-flow capsule told me to read `HowItWorks`; the API-pattern capsule tried to steer toward irrelevant auth-page handlers; the `updateSite` capsule suggested a caller page before the core abstraction. Likely root cause is score-only follow-up selection in [`src/capsule/formatter.ts`](/Users/aejjusingh/Developer/ContextWeave/src/capsule/formatter.ts) without task-role awareness. Fix: suggestion ranking should favor route handlers, shared helpers, and central abstraction files that match the query intent, not merely the highest compressed-score symbol.
3. **Budget utilization is still far below the product claim on hard queries**: with 8k budgets, the two architectural queries used only 43% and 24% of the budget. That is exactly the failure mode ContextWeave claims to have moved past. Likely root cause is early stopping and weak story-complete packing in [`src/capsule/packer.ts`](/Users/aejjusingh/Developer/ContextWeave/src/capsule/packer.ts) and [`src/capsule/generator.ts`](/Users/aejjusingh/Developer/ContextWeave/src/capsule/generator.ts). Fix: keep packing coherent first-party evidence until either coverage thresholds are satisfied or utilization reaches a healthy floor for broad tasks.
4. **`cw_flow` is still shaky on direct cross-file calls**: `cw_flow("src/lib/dataLayer.ts:updateSite")` did not show the actual cross-file hop into `src/lib/supabase/queries.ts:updateSite`; it skipped straight to inner helper callees. That makes the trace look smarter than it is while hiding the most important boundary. Likely root cause is callee-resolution around wrapper/dynamic-import calls in [`src/core/indexer.ts`](/Users/aejjusingh/Developer/ContextWeave/src/core/indexer.ts) and rendering/traversal in [`src/mcp/tools/flow.ts`](/Users/aejjusingh/Developer/ContextWeave/src/mcp/tools/flow.ts). Fix: preserve the explicit first cross-file callee in the rendered path even when deeper inner callees are known.
5. **`cw_status` failed to flag a dangerously stale/partial index**: the first status showed `47` files / `883` symbols; after `cw_reindex` the same project became `647` files / `4102` symbols. `cw_status` treated the earlier state as healthy. Likely root cause is weak index-health checks in [`src/mcp/tools/status.ts`](/Users/aejjusingh/Developer/ContextWeave/src/mcp/tools/status.ts). Fix: track last-discovery counts and emit a strong warning when indexed file count is implausibly below the current project footprint.

### P2 (Moderate — papercut)
1. **`cw_overview` overweights tests in route scopes**: under `src/app/api`, the top files by symbol count were dominated by route tests, which dilutes the architectural picture. Likely root cause is naive symbol-count sorting in [`src/mcp/tools/overview.ts`](/Users/aejjusingh/Developer/ContextWeave/src/mcp/tools/overview.ts). Fix: production files should outrank tests by default, with an explicit switch to include test-heavy views.
2. **`cw_recall` delivered no practical value here**: `cw_recall("submit inquiry")` returned nothing useful, which makes the memory surface feel ornamental rather than helpful in real code review work. Likely root cause is retrieval/seed strategy in [`src/memory/search.ts`](/Users/aejjusingh/Developer/ContextWeave/src/memory/search.ts). Fix: if durable memory is empty, say so clearly and optionally surface nearby architectural docs or recent relevant observations instead of a dead-end.
3. **`cw_stats` is easy to misread**: it reported `Indexed: 36 files, 99 symbols`, `First-pass rate: 100%`, `Correction rate: 0%`, and `Avg follow-up reads: 0.00` after a session that obviously required repeated recovery. Likely root cause is formatting and scope labeling in [`src/mcp/tools/stats.ts`](/Users/aejjusingh/Developer/ContextWeave/src/mcp/tools/stats.ts), plus dependence on external hook plumbing. Fix: label session-local stats explicitly, expose whether follow-up tracking hooks are active, and avoid “healthy” language when the session clearly relied on rescue exploration.
