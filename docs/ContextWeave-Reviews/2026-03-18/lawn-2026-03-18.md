## Flaws Found

Ordered by severity. Each flaw includes what happened, likely root cause, and a fix direction.

### P0 (Critical — blocks adoption)
1. **Confidence is dangerously overstated on wrong answers**: `cw_capsule("invite acceptance flow from UI to mutation to database")` reported `Confidence: HIGH` while stuffing the capsule with `convex/videos.ts`, `convex/_generated/server.js`, and billing files instead of the actual invite flow. Likely root cause: confidence scoring overweights raw pivot/dependency coverage and underweights story completeness and irrelevant-cluster pollution. Suggested fix: gate HIGH confidence on end-to-end intent coverage, penalize off-topic files, and explicitly downrank generated files.

2. **Impact analysis misses real framework callers**: `cw_impact(target: "resolveContext")` returned `No dependents found` even though the function is used in four dashboard data modules. Likely root cause: the graph is not connecting Convex `api.workspace.resolveContext` references in React files back to `convex/workspace.ts`. Suggested fix: add Convex-aware symbol aliasing/edge construction for `api.*.*` query and mutation references and generated API wrappers.

3. **Architectural capsules collapse into route boilerplate instead of core implementation**: the prewarming architecture query returned mostly `Route` declarations and suggested reading `Route`, not `src/lib/convexRouteData.ts` or `src/lib/useRoutePrewarmIntent.ts`. Likely root cause: ranking/packing is biased toward common exported route symbols and file clusters, with weak intent modeling for architecture/pattern questions. Suggested fix: add architecture-intent heuristics that boost shared library hubs, fan-out utilities, and repeated call targets while suppressing route shell boilerplate.

### P1 (Important — degrades quality)
1. **Follow-up suggestions are frequently low-value or wrong**: for `resolveContext`, it suggested `cw_read(symbol: "fullTitle")`; for the invite flow, it suggested `cw_read(symbol: "invite")`; for prewarming, it suggested `cw_read(symbol: "Route")`. Likely root cause: follow-up ranking is driven by local score without enough task-intent filtering or generic-name suppression. Suggested fix: only suggest file-qualified or uniquely identifying symbols when ambiguity is high, and diversify suggestions by intent.

2. **Measured token savings are far below the product claim**: across three real tasks, ContextWeave saved `41.2%`, not the claimed `60-70%`. Likely root cause: the system still requires too many corrective reads after bad initial ranking, and broad capsules do not deliver story-complete results. Suggested fix: optimize for fewer corrective follow-ups, not just smaller first capsules.

3. **Large token budgets are barely used**: both `8000`-token tests used under `8%` of budget. Likely root cause: the packer stops after a thin retrieval set and does not expand evidence even when there is budget headroom. Suggested fix: add budget-aware expansion passes until either marginal relevance drops or a reasonable utilization floor is reached.

4. **Search and overview are polluted by plans/docs/generated files**: `cw_grep("resolveContext")` ranked tests and plan docs above the actual definition; `cw_overview("route prewarming")` mixed useful files with generic route noise. Likely root cause: ranking weights for docs/tests/generated artifacts are too high for code-understanding queries. Suggested fix: default-rank source code above tests/docs/generated files unless the query explicitly asks for docs or plans.

5. **Session metrics overstate success**: `cw_stats()` said `First-pass rate: 100.0%` and `Estimated savings: 91% reduction` after a single easy session, while the measured three-task review landed at `41.2%` savings and repeated manual correction. Likely root cause: stats are session-local and based on optimistic estimates rather than measured task outcomes. Suggested fix: distinguish estimated vs measured savings, and track corrections/fallbacks at the task level.

### P2 (Moderate — papercut)
1. **Reindex error reporting is opaque**: `cw_reindex({})` reported `1 errors`, but `cw_status(verbose: true)` did not surface which file failed or why. Likely root cause: indexer errors are counted but not threaded into status output or a failure list. Suggested fix: include failing paths and error reasons in both `cw_reindex` and `cw_status`.

2. **`cw_recall` adds little value in a cold-start review**: `cw_recall("route prewarm")` returned `No observations found`. Likely root cause: the tool depends on prior intentional memory, but the UX does not make that limitation obvious. Suggested fix: when memory is empty, say that explicitly and suggest the next-best retrieval tool instead of returning a dead-end.
