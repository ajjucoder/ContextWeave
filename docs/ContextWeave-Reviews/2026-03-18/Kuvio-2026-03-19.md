## Flaws Found

### P0 (Critical — blocks adoption)

1. **`.gitignore` subdirectory pattern causes entire parent directory exclusion**: The `.gitignore` contains `src/lib/stores/` (a subdirectory pattern). ContextWeave interprets this as excluding the entire `src/` directory. Same bug: `supabase/.temp/` causes all of `supabase/` to be excluded. This renders the tool completely non-functional — 0 of 567 source files indexed, 0 of ~99,500 lines of code accessible. Root cause: likely in the gitignore parser — it's matching the first path component (`src`) as a root-level exclusion instead of only matching the specific subdirectory path `src/lib/stores/`. Fix: implement proper gitignore path matching that respects directory depth. `src/lib/stores/` should only exclude files under `src/lib/stores/`, not everything under `src/`.

2. **No `cw_reindex` tool available**: The cw_status output says "Run cw_reindex first" when the index is empty, and the review prompt assumes `cw_reindex()` exists, but no such tool is exposed via MCP. When the index breaks (as it did here), there is zero recovery path from within the agent session. The user would need to manually delete `.contextweave/contextweave.db` and restart the MCP server — but this isn't documented anywhere in the tool's error messages. Fix: expose `cw_reindex` as an MCP tool, or at minimum provide actionable recovery instructions in error messages.

3. **Database corruption with no recovery**: The `.contextweave/` directory contains two `.corrupt.*` files (`contextweave.db.corrupt.1773824599281` and `contextweave.db.corrupt.1773858551506`), indicating the database has corrupted at least twice. Combined with the missing reindex tool, this means corruption is both recurring and unrecoverable without manual intervention. Fix: implement WAL checkpointing, add corruption detection on startup with automatic rebuild, and expose reindex via MCP.

### P1 (Important — degrades quality)

4. **Observation retrieval returns irrelevant noise**: When querying "data layer architecture patterns" or "authentication middleware", cw_recall returns design prompt documentation (cyberpunk themes, SaaS UI patterns, CSS gradients) alongside the actually-relevant ARCHITECTURE.md entries. 6 of 10 results for "data layer architecture" are completely irrelevant design prompt files. Root cause: BM25 text matching on common words ("patterns", "architecture") without semantic filtering or source-type weighting. Fix: weight source-code observations higher than documentation snippets, or add a relevance threshold that filters out low-scoring matches.

5. **All observations scored at flat 0.50 confidence**: Every observation in every response has exactly `confidence: 0.50` — no differentiation between a highly relevant ARCHITECTURE.md entry about data layer modes and an irrelevant design prompt about CSS gradients. Root cause: likely the observation recording doesn't compute per-observation confidence, just assigns a default. Fix: compute actual relevance scores based on query-observation similarity.

6. **Diagnostics are misleading when index is empty**: Every capsule includes a "Diagnostics" section that says `Bottleneck: none` and `Suggestion: No immediate action needed. Keep monitoring this query class over time.` — even when the index contains 0 files and 0 symbols. The most obvious bottleneck possible (no data) goes undetected. Fix: add an index health check to the diagnostics pipeline — if indexed files = 0, the diagnostic should say "Index is empty — run cw_reindex or check exclusion patterns."

7. **`cw_grep` error message references non-existent tool**: Returns "No indexed files available. Run cw_reindex first." but `cw_reindex` is not an exposed MCP tool. This is a dead-end error that provides no actionable path forward. Fix: either expose `cw_reindex` or change the error message to something actionable (e.g., "No indexed files. Check .gitignore exclusion patterns or restart the MCP server to trigger reindexing.").

### P2 (Moderate — papercut)

8. **"First-pass rate: 100%" is a misleading metric**: After 10 capsules that all returned 0 results, the stats report "First-pass rate: 100%". This metric measures whether the user issued correction queries, not whether the capsule was useful. A 100% first-pass rate with 0% budget utilization and 0 symbols returned is nonsensical. Fix: don't count capsules with 0 results toward the first-pass rate, or add a separate "empty capsule rate" metric.

9. **`cw_status` does not report ContextWeave version**: The status output includes file/symbol/edge counts and LSP bridge status, but no version string. This makes it impossible to file reproducible bug reports or track regressions. Fix: include version in cw_status output.

10. **Coverage confidence varies without meaningful basis**: Narrow queries get 20% coverage confidence while broad queries get 9%, but both return identical 0 results from an empty index. The variation creates a false impression of differential analysis when there's nothing to analyze. Fix: when index is empty, report 0% confidence uniformly with an explicit "index empty" flag.

11. **Budget underutilization advice is wrong**: The system says "Consider narrowing your query or using cw_grep for broader text coverage" when budget is underutilized. But the problem is the empty index, not query formulation. This wastes the user's time trying different queries when no query can succeed. Fix: detect empty index and provide the correct advice (fix exclusion patterns / reindex).

## What Worked Well

1. **Confidence labels are directionally correct**: LOW/CRITICAL uncertainty flags are honest — the system doesn't claim HIGH confidence when it has nothing. The labels themselves are trustworthy; the issue is the diagnostics contradicting them.

2. **Quality notes are specific and useful**: Bullet points like "no pivot symbol match", "query term coverage below 60%", "retrieval surface too thin" are clear, actionable diagnostic signals. If the index were populated, these would help the user understand why a query underperformed.

3. **Intent classification works**: The system correctly classifies `mapSite` as "symbol-lookup" (narrow) and "data layer architecture" as "broad". It also correctly identifies multi-pass strategies for complex queries. The classification layer works even without data.

4. **Graceful degradation of cw_capsule**: Despite returning no results, capsules don't crash, don't hang, and return structured metadata with suggested next actions. The failure mode is clean — just unhelpful due to the downstream advice issues noted above.

5. **Observation memory persists across sessions**: The 24 observations (from prior sessions, recorded against docs/ files) survived the database corruption events. This suggests the observation store is somewhat resilient.

**Note:** This review is fundamentally constrained by the `.gitignore` parsing bug. With a working index, ContextWeave might perform significantly better — but the bug itself is the most critical finding. A tool that silently excludes all source code due to a common `.gitignore` pattern will fail on many real-world projects. If this pattern breaks indexing, it will affect a large percentage of potential users.
